# Промпт для Claude Code: платформа аналитики рекламы и продаж

> Как использовать: положи этот файл в корень пустой папки проекта, открой Claude Code и напиши:
> «Прочитай PROMPT.md целиком. Задай мне вопросы, если что-то неясно, затем начни с Фазы 0. После каждой фазы останавливайся и показывай результат».

---

## 1. Что мы строим

SaaS-платформа (рабочее название **AdScope**, название можно поменять). Любая компания с отделом продаж и/или таргетированной рекламой регистрируется, подключает рекламные кабинеты **Meta (Facebook/Instagram)** и **TikTok Ads**. Платформа показывает, **какая кампания, группа объявлений, объявление и креатив реально приносят продажи и прибыль**, а не только клики и лиды.

Главный вопрос, на который платформа отвечает: **«Куда тратятся деньги и что из этого приносит прибыль?»**

Цепочка данных:
```
Расход (Meta/TikTok API) → Лид (номер телефона + источник) → Продажа (внёс менеджер / CRM / таблица) → Прибыль
```
Связка лида и продажи идёт **по номеру телефона**: менеджер вносит продажу с номером клиента, система находит этот номер среди лидов и автоматически определяет, с какого объявления пришёл клиент.

В первой версии платформа **только читает** данные рекламных кабинетов (read-only). Никаких изменений в рекламе через API.

## 2. Технологический стек

- **Next.js 15 (App Router) + TypeScript**, строгий режим
- **Tailwind CSS + shadcn/ui** (компоненты), **Framer Motion** (анимации), **Recharts** (графики), **lucide-react** (иконки)
- **Supabase**: Postgres, Auth (email + Google), Row Level Security, Storage (превью креативов), Edge Functions, pg_cron (фоновые задачи)
- **Деплой**: Vercel
- **AI**: Claude API (Anthropic SDK). Актуальную модель бери из docs.claude.com, имя модели храни в env.
- Валидация: zod. Даты: date-fns с учётом часового пояса рекламного аккаунта.
- Все секреты только в env. Токены рекламных кабинетов хранятся **зашифрованными** (Supabase Vault или AES-256-GCM с ключом из env) и никогда не уходят на клиент.

## 3. Мультитенантность

- Сущность **workspace** (компания). У пользователя может быть несколько workspace, есть переключатель.
- Все таблицы с данными содержат `workspace_id`, доступ ограничен через RLS.
- Владелец приглашает участников по email/ссылке.
- **Ролей пока нет**: в v1 все участники workspace видят всё. Но в таблице `workspace_members` сразу заложи поле `role` (по умолчанию `member`, у создателя `owner`), чтобы роли добавить позже без миграции данных.

## 4. Подключение рекламных кабинетов

### 4.1 Meta (Facebook / Instagram)
- OAuth через Facebook Login for Business. Разрешения: `ads_read`, `business_management`, `pages_show_list`, `pages_read_engagement`, `leads_retrieval`, `pages_manage_metadata` (для вебхука лид-форм). Для Instagram Direct: `instagram_basic`, `instagram_manage_messages`.
- После авторизации показать список доступных рекламных аккаунтов с чекбоксами, пользователь выбирает нужные.
- Для каждого аккаунта сохранить `currency`, `timezone_name`, `account_status`.
- Структура: Campaign → Ad Set → Ad → Creative. Синхронизировать названия, статусы, бюджеты, цели, даты.
- Статистика: `/act_{id}/insights`, `level=ad`, `time_increment=1`. Поля: spend, impressions, reach, frequency, clicks, inline_link_clicks, ctr, cpc, cpm, actions, action_values, cost_per_action_type. Разобрать `actions` на leads, purchases, messaging_conversations_started.
- Креативы: thumbnail_url, image_url, video_id, body, title, call_to_action. **Ссылки на превью у Meta протухают**, поэтому скачивай превью в Supabase Storage.
- Реализовать обязательный для Meta **Data Deletion Callback** и страницу Privacy Policy.
- Учитывать rate limits (заголовки `x-business-use-case-usage`), экспоненциальные ретраи, батч-запросы.

### 4.2 TikTok Ads
- OAuth авторизация рекламодателя (TikTok for Business Marketing API v1.3).
- `/advertiser/info/`: валюта, часовой пояс.
- Структура: Campaign → Ad Group → Ad.
- Статистика: `/report/integrated/get/`, `data_level=AUCTION_AD`, разбивка по дням. Метрики: spend, impressions, reach, clicks, ctr, cpc, cpm, conversion, cost_per_conversion, video_play_actions, video_watched_2s, video_watched_6s, average_video_play.
- Превью видео через `/file/video/ad/info/`, обложки тоже кешируй в Storage.

### 4.3 Синхронизация
- При первом подключении: загрузка за последние 90 дней с прогресс-баром.
- Далее cron каждые 1–2 часа: последние 3 дня (данные в кабинетах пересчитываются задним числом).
- Таблица `sync_runs` со статусом, ошибками и временем. В UI видно «Обновлено 12 минут назад» и кнопка «Обновить сейчас».
- Если токен истёк или отозван, баннер «Переподключите кабинет».

### 4.4 Важно про доступ (описать в README)
Пока приложение Meta в режиме разработки, подключить можно только аккаунты, где у пользователя есть роль в приложении. Чтобы подключались любые компании, нужны **Business Verification + App Review** (Advanced Access для `ads_read` и др.). У TikTok своё одобрение приложения. Claude Code должен подготовить демо-режим на моковых данных, чтобы разработка и показ клиентам не зависели от ревью.

## 5. Лиды и атрибуция (главная логика)

Все источники складываются в одну таблицу `leads`: телефон (нормализованный), имя, источник, platform, campaign_id, adset_id, ad_id, created_at, raw_payload.

### Источники лидов
1. **Лид-формы Meta**: вебхук `leadgen` на странице → по `leadgen_id` получить лид с `ad_id`, `adset_id`, `campaign_id`, `form_id`, `field_data` (телефон). Плюс периодическая догрузка через API на случай пропущенных вебхуков.
2. **Лид-формы TikTok** (Instant Form): подписка на лиды / выгрузка через API.
3. **Сайт с UTM-метками**:
   - Сгенерировать для пользователя готовую строку URL-параметров для кабинетов:
     - Meta: `utm_source=facebook&utm_medium=paid&utm_campaign={{campaign.id}}&utm_term={{adset.id}}&utm_content={{ad.id}}`
     - TikTok: `utm_source=tiktok&utm_medium=paid&utm_campaign=__CAMPAIGN_ID__&utm_term=__AID__&utm_content=__CID__`
   - Небольшой JS-сниппет для сайта: сохраняет UTM, fbclid, ttclid в cookie на 30 дней и подставляет их в скрытые поля форм.
   - Публичный endpoint `POST /api/ingest/lead` с ключом workspace, куда сайт или Tilda/вебхук отправляет телефон + UTM.
4. **WhatsApp (Click-to-WhatsApp)**: если клиент использует WhatsApp Business Platform (Cloud API), вебхук входящего сообщения содержит объект `referral` с `source_id` (ID объявления) и `ctwa_clid`. Сохраняем номер отправителя как лид с привязкой к объявлению. В UI честно предупредить: в обычном приложении WhatsApp Business этих данных нет, нужен Cloud API или провайдер (Wazzup, 360dialog и т.п.).
5. **Instagram Direct**: вебхук сообщений Instagram с `referral.ad_id` для рекламы «Отправить сообщение».
6. **Ручной лид**: менеджер вручную указывает источник из списка кампаний и объявлений.

### Нормализация телефона
- Привести к E.164 (`libphonenumber-js`), страна по умолчанию KZ: `8 701 ...` → `+7701...`, убрать пробелы, скобки, дефисы.
- Хранить `phone_normalized` с индексом.

### Атрибуция продажи
- При добавлении продажи ищем лиды с тем же `phone_normalized` в этом workspace.
- Модель по умолчанию: **последнее касание** в окне 30 дней до продажи. В настройках выбор: последнее / первое касание, окно 7/14/30/60/90 дней.
- Если лидов несколько, в карточке продажи показать всю историю касаний.
- Если лид не найден, продажа помечается «Источник не определён». Менеджер может выбрать источник вручную, отдельный счётчик таких продаж виден на дашборде (это метрика качества данных).

## 6. Продажи и прибыль

### Как продажи попадают в систему (все варианты)
1. **Ручной ввод менеджером**. Это самый главный сценарий, он должен быть максимально быстрым:
   - Большая кнопка «+ Продажа» доступна с любого экрана (на телефоне плавающая кнопка).
   - Поля: телефон клиента (автоформат), сумма, товар/услуга (опционально), себестоимость (подставляется из товара), дата (по умолчанию сегодня), комментарий.
   - Сразу после ввода номера показываем найденный источник: «Клиент пришёл с объявления "Видео_отзыв_3" · Meta · 5 дней назад».
   - Добавление за 10–15 секунд с телефона.
2. **Импорт CSV / Excel** с мастером сопоставления колонок (телефон, сумма, дата, товар), предпросмотром и отчётом о дубликатах.
3. **Google Sheets**: подключение таблицы, автоматическая синхронизация раз в час.
4. **amoCRM и Bitrix24**: OAuth, вебхуки на смену статуса сделки. Пользователь выбирает, какой статус считается «Успешно реализовано». Тянем телефон контакта, сумму сделки, дату.
5. **Пиксель / конверсии из кабинетов**: purchases и purchase value из Meta/TikTok показываем **отдельной колонкой** «По данным пикселя» рядом с реальными продажами, чтобы было видно расхождение. Не смешиваем с реальными продажами.

### Дедупликация
Одна и та же продажа может прийти из CRM и вручную. Ключ дубля: телефон + сумма + дата ±1 день. Показывать предупреждение, не удалять молча.

### Себестоимость и прибыль
- Справочник товаров/услуг: название, цена, себестоимость (сумма или %).
- Глобальная настройка «Средняя маржа %» на случай, если товары не заведены.
- **Прибыль = Выручка − Себестоимость − Расход на рекламу**.

## 7. Валюта (обязательная логика)

- **Основная валюта отображения = валюта рекламного аккаунта.** Аккаунт в USD, значит цифры в USD.
- Под каждой денежной суммой на карточках и в таблицах **тонкий мелкий серый текст** с суммой во второй валюте: `$1 240.50` и под ним `≈ 632 655 ₸`.
- Если аккаунт в тенге, вторая валюта USD (настраивается в настройках workspace).
- **Курс берём у Национального банка РК** автоматически: ежедневный cron в 10:00 по Алматы, официальный RSS/XML курсов НБРК (`nationalbank.kz/rss/get_rates.cfm?fdate=ДД.ММ.ГГГГ`). Сохраняем в таблицу `exchange_rates (date, currency, rate_to_kzt)`. Выходные и праздники = последний известный курс.
- Конвертация **по курсу на дату расхода/продажи**, а не по сегодняшнему.
- Продажи менеджеры вносят в валюте workspace (по умолчанию ₸). Для ROAS/прибыли всё приводится к валюте аккаунта по курсу на дату продажи.
- Если в workspace несколько аккаунтов в разных валютах, на общем дашборде переключатель «Показать в: USD / KZT».
- Рядом со второй валютой иконка-подсказка: «Курс НБРК на 12.10.2026: 1 USD = 510.20 ₸».

## 8. Метрики

На каждом уровне (аккаунт / кампания / группа / объявление / креатив):

| Группа | Метрики |
|---|---|
| Расход | Spend, Impressions, Reach, Frequency, CPM |
| Клики | Clicks, CTR, CPC |
| Лиды | Лиды, CPL (стоимость лида) |
| Продажи | Кол-во продаж, Выручка, Конверсия лид→продажа, CAC (стоимость продажи), Средний чек |
| Прибыль | Прибыль, ROAS (выручка/расход), ROMI ((прибыль)/расход × 100%) |
| Видео (TikTok/Meta) | Hook rate (3с/показы), Hold rate, средний просмотр |

**Рейтинг креатива (0–100)** на основе ROMI, CAC, конверсии лид→продажа и CTR с учётом объёма данных: креатив с 2 продажами не должен обгонять креатив со 100 продажами. Используй байесовское сглаживание или минимальный порог. Бейджи: «🔥 Лидер», «📈 Растёт», «⚠️ Выгорает», «❌ Сливает бюджет», «⏳ Мало данных».

## 9. AI-рекомендации

Гибридная схема:
1. **Детерминированные правила** (SQL/TS) находят сигналы:
   - Расход > 2× целевого CAC и 0 продаж → «Отключить или переработать»
   - ROMI выше цели и стабилен 3+ дня → «Масштабировать бюджет»
   - Frequency > 3 и CTR падает 3 дня подряд → «Креатив выгорает»
   - Много лидов, мало продаж → «Проблема в качестве лидов или в обработке отделом продаж»
   - Много продаж без источника → «Проверьте UTM / подключите лид-формы»
2. **Claude API** получает сигналы + агрегированные цифры (без персональных данных клиентов, без телефонов) и пишет понятные рекомендации на русском: что случилось, почему это важно, что сделать. Ответ строго в JSON по zod-схеме.
3. Экран «AI-советы»: карточки с приоритетом (высокий/средний/низкий), ссылкой на объект, кнопками «Полезно / Не полезно / Скрыть».
4. Чат «Спроси AI про рекламу»: вопрос свободным текстом, ответ на основе данных workspace (через tool use с безопасными агрегирующими функциями, без прямого SQL от модели).
5. Генерация раз в день + по кнопке. Кешировать, логировать стоимость токенов.

Целевые CAC и ROMI задаются в настройках workspace. Пока не заданы, AI предлагает их по историческим данным.

## 10. Экраны

1. **Лендинг** (публичный): яркий hero, демо дашборда, тарифы-заглушка, кнопка «Попробовать».
2. **Регистрация / вход**, создание workspace.
3. **Онбординг-мастер** (пошагово, с прогрессом и анимацией): подключить Meta → подключить TikTok → настроить источники лидов (лид-формы / UTM-сниппет / WhatsApp) → способ ввода продаж → валюта и себестоимость → пригласить команду. Каждый шаг можно пропустить.
4. **Дашборд**: KPI-карточки (Расход, Лиды, Продажи, Выручка, Прибыль, ROMI) с анимированными счётчиками и дельтой к прошлому периоду; график расход vs выручка по дням; топ-5 креативов; блок AI-советов; воронка показы → клики → лиды → продажи.
5. **Кампании**: таблица-дерево Кампания → Группа → Объявление с раскрытием, сортировкой по любой метрике, фильтрами (платформа, аккаунт, статус, период), выбором колонок, цветовой подсветкой ROMI (красный → жёлтый → зелёный).
6. **Креативы**: галерея карточек с превью (видео проигрывается при наведении), рейтинг, бейдж, ключевые цифры; переключатель сетка/таблица; страница креатива с графиком по дням и списком продаж.
7. **Лиды**: список с источником, статусом (есть продажа / нет), поиском по телефону.
8. **Продажи**: список, быстрое добавление, импорт, фильтр «без источника».
9. **AI-советы** и чат.
10. **Настройки**: подключения (статус, переподключить, отключить), источники лидов (UTM-строки для копирования, сниппет, вебхук-URL), атрибуция, валюта, товары и себестоимость, цели CAC/ROMI, команда, workspace.

Глобально: выбор периода (сегодня, вчера, 7, 14, 30 дней, этот месяц, произвольный) и сравнение с прошлым периодом.

## 11. Дизайн: светлый и яркий

**Настроение**: светлый, чистый, сочный, дорогой. Белые карточки на очень светлом фоне, насыщенные акцентные градиенты, много воздуха. Не скучная бухгалтерия, а продукт, который приятно открывать.

**Палитра (CSS-переменные / Tailwind theme):**
- Фон: `#F6F7FB`, карточки `#FFFFFF`, границы `#E8EAF2`
- Primary градиент: `#6D5BFF → #3D8BFF` (кнопки, активные элементы, hero)
- Accent: коралловый `#FF5C7A`, солнечный `#FFB020`
- Прибыль/рост: `#12B76A`, убыток: `#F04438`, предупреждение: `#F79009`
- Текст: `#101828`, вторичный `#667085`, тонкая подпись валюты `#98A2B3`
- Платформы: Meta `#0866FF`, TikTok чёрный с бирюзово-розовым акцентом

**Типографика:** шрифты с хорошей кириллицей, например Onest или Manrope для текста и Unbounded для крупных цифр и заголовков. Цифры с `tabular-nums`, разделители тысяч пробелом (`1 240 500 ₸`).

**Компоненты:** скругления 16–20px, мягкие цветные тени (`0 8px 24px rgba(109,91,255,0.12)`), иконки в цветных «таблетках», бейджи-пилюли.

**Анимации (Framer Motion), плавно и не навязчиво:**
- Появление карточек каскадом (stagger) при загрузке страницы
- Count-up для KPI-цифр
- Кнопки: hover приподнимается + усиливается тень, press: scale 0.97, у primary-кнопки лёгкий переливающийся градиент
- Плавные переходы между страницами и табами, анимированный индикатор активного таба
- Скелетоны вместо спиннеров
- Конфетти-микроанимация при подключении кабинета и при добавлении продажи
- Графики рисуются с анимацией
- Обязательно уважать `prefers-reduced-motion`

**Адаптивность (mobile-first):**
- Телефон: нижняя навигация (5 пунктов) + плавающая кнопка «+ Продажа»; таблицы превращаются в карточки; фильтры в bottom sheet; KPI в горизонтальном скролле; всё нажимается пальцем (минимум 44px).
- Планшет: сворачиваемый сайдбар.
- Десктоп: сайдбар слева, широкие таблицы с закреплённой первой колонкой.
- Проверить ширины 375, 768, 1280, 1440.

Пустые состояния: дружелюбная иллюстрация + понятное действие («Подключите первый кабинет»). Тексты интерфейса на русском, весь текст вынесен в i18n-файл (чтобы позже добавить казахский/английский).

## 12. Модель данных (ориентир)

## 13. Порядок работы (фазы)

Работай по фазам. После каждой: короткий отчёт, как проверить, и остановка для моего подтверждения.

- **Фаза 0. Основа и дизайн**: проект, дизайн-система, все экраны на **моковых данных** (реалистичный сид: 2 аккаунта, 6 кампаний, 40 объявлений, 300 лидов, 80 продаж, в USD и KZT). Цель: сразу увидеть и потрогать дизайн на телефоне и компьютере.
- **Фаза 1. Auth + workspace + Supabase-схема + RLS**.
- **Фаза 2. Meta**: OAuth, выбор аккаунтов, синк структуры, статистики, креативов.
- **Фаза 3. TikTok**: то же самое.
- **Фаза 4. Лиды**: лид-формы, UTM-сниппет + ingest endpoint, WhatsApp/Instagram вебхуки, нормализация телефонов.
- **Фаза 5. Продажи**: ручной ввод, атрибуция, товары/себестоимость, CSV, Google Sheets, amoCRM, Bitrix24.
- **Фаза 6. Валюта**: курсы НБРК, двойное отображение.
- **Фаза 7. AI-рекомендации и чат**.
- **Фаза 8. Полировка**: производительность, анимации, пустые состояния, ошибки, тесты ключевой логики (нормализация телефона, атрибуция, конвертация валют, расчёт ROMI), README с инструкцией по настройке Meta/TikTok приложений.
